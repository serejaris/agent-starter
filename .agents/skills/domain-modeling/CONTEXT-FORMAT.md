# Формат CONTEXT.md

## Структура

```md
# {Имя контекста}

{Одно-два предложения: что это за контекст и зачем он существует.}

## Язык

**Order**:
{Одно-два предложения с определением термина}
_Не использовать_: Purchase, transaction

**Invoice**:
Запрос на оплату, который отправляют клиенту после поставки.
_Не использовать_: Bill, payment request

**Customer**:
Человек или организация, которые размещают заказы.
_Не использовать_: Client, buyer, account
```

## Правила

- **Будь категоричен.** Когда на одно понятие есть несколько слов, выбери лучшее, остальные перечисли в `_Не использовать_`.
- **Держи определения короткими.** Максимум одно-два предложения. Определяй, что это ЕСТЬ, а не что оно делает.
- **Включай только термины этого контекста.** Общие программистские понятия (таймауты, типы ошибок, утилитарные паттерны) сюда не относятся, даже если проект ими густо пользуется. Перед добавлением термина спроси: это понятие уникально для этого контекста или общее программистское? Только первое сюда относится.
- **Группируй термины под подзаголовками**, когда появляются естественные кластеры. Если все термины из одной связной области, плоский список нормален.

## Один контекст или несколько

**Один контекст (большинство репозиториев):** один `CONTEXT.md` в корне репозитория.

**Несколько контекстов:** `CONTEXT-MAP.md` в корне репозитория перечисляет контексты, где они живут и как связаны:

```md
# Карта контекстов

## Контексты

- [Ordering](./src/ordering/CONTEXT.md): принимает и ведёт заказы клиентов
- [Billing](./src/billing/CONTEXT.md): выставляет счета и проводит платежи
- [Fulfillment](./src/fulfillment/CONTEXT.md): собирает заказы на складе и отгружает

## Связи

- **Ordering → Fulfillment**: Ordering публикует события `OrderPlaced`; Fulfillment их потребляет и начинает сборку
- **Fulfillment → Billing**: Fulfillment публикует события `ShipmentDispatched`; Billing их потребляет и выставляет счета
- **Ordering ↔ Billing**: общие типы `CustomerId` и `Money`
```

Скилл сам понимает, какая структура действует:

- Если есть `CONTEXT-MAP.md`, прочитай его, чтобы найти контексты
- Если есть только корневой `CONTEXT.md`, контекст один
- Если нет ни того ни другого, создай корневой `CONTEXT.md` лениво, когда разрешён первый термин

Когда контекстов несколько, определи, к какому относится текущая тема. Если неясно, спроси.
