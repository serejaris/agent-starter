# hq: проверка и настройка штаба

Штаб это папка, с которой начинается работа с агентом: файл правил, `me.md`, карта отделов. Скилл проходит её по восьми шагам и отвечает таблицей ✓/✗.

Сам скилл меняет только раскладку: пишет `stack/harness.md`, решает, какой из двух файлов правил настоящий, чинит симлинки и папку скиллов. Текст правил и `me.md` он меняет только после «да» человека и сначала показывает правку. Правила за человека он не пишет, отделы не создаёт, чужие файлы не трогает.

Команды даны для macOS и Linux (zsh, bash). На Windows агент делает то же средствами PowerShell.

## 1. Найти штаб

```sh
pwd
for f in AGENTS.md CLAUDE.md me.md stack/harness.md; do { [ -e "$f" ] || [ -L "$f" ]; } && echo "есть $f"; done
```

- Есть `me.md` или `stack/harness.md`: штаб это текущая папка.
- Есть только файл правил, и он ссылается на штаб в другой папке (например `../hq`): открыт отдел, штаб берётся по этой ссылке.
- Есть только файл правил без такой ссылки: до любых правок спросить одной строкой, штаб ли это. Такая папка может оказаться отделом или проектом.
- Нет ничего: поискать уровнем ниже. Если нашлось, агент открыт в родительской папке. Сказать об этом, назвать найденные папки и попросить открыть агента в самом штабе.

  ```sh
  find . -mindepth 2 -maxdepth 2 \( -name AGENTS.md -o -name CLAUDE.md -o -name me.md \)
  ```

- Не нашлось и там: спросить путь к штабу одной строкой.

Дальше команды выполняются в папке штаба по её настоящему пути: `cd <штаб> && cd "$(pwd -P)"`.

Путь должен быть латиницей: кириллица в пути ломает часть команд агента.

```sh
pwd -P | LC_ALL=C grep -q '[^ -~]' && echo "✗ в пути есть не латинские символы"
```

## 2. Харнес и модель

Харнес определяется по переменным окружения, сверху вниз:

| Условие | Харнес | Версия |
|---|---|---|
| `CLAUDECODE=1` | Claude Code, точка входа из `CLAUDE_CODE_ENTRYPOINT` (`cli`, `claude-desktop`) | `"${CLAUDE_CODE_EXECPATH:-claude}" --version` |
| есть переменные `CODEX_*` | Codex | `codex --version` |
| есть переменные `ZCODE_*` | ZCode | значение `ZCODE_APP_VERSION` |
| ничего из этого | unknown | нет |

```sh
echo "CLAUDECODE=$CLAUDECODE ENTRYPOINT=$CLAUDE_CODE_ENTRYPOINT"
env | grep -E '^(CODEX_|ZCODE_)' | cut -d= -f1
for c in claude codex gemini cursor-agent opencode kimi droid grok omp hermes; do command -v "$c" >/dev/null 2>&1 && echo "$c"; done
date +%F
```

Модель агент называет сам: она записана в его системном промпте или настройках харнеса. Если не знает, пишет «не определена». Точку входа другого харнеса агент тоже называет сам, если знает.

Записать `stack/harness.md` по образцу, папку `stack/` создать, если её нет. Другие агенты на машине: найденные команды из списка, кроме своей. Если файл уже есть и отличается только датой, его не трогать. Иначе перезаписать целиком, а строки, которые человек дописал под таблицей сам, перенести как есть.

```markdown
# Харнес

Харнес и модель, в которых работает агент штаба. От харнеса зависит, какой файл правил главный. Файл пишет скилл `hq`, здесь только текущее состояние.

| Поле | Значение |
|---|---|
| Харнес | <харнес> |
| Точка входа | <точка входа> |
| Версия | <версия> |
| Модель | <модель> |
| Проверено | <ГГГГ-ММ-ДД> |
| Главный файл правил | <по шагу 3, например: `CLAUDE.md`, `AGENTS.md` симлинк на него> |
| Другие агенты на машине | <команды через запятую> |
```

## 3. Главный файл правил под харнес

Текст правил один, а файлов два. Главный файл настоящий, второй это симлинк на него:

- Claude Code: главный `CLAUDE.md`, `AGENTS.md` симлинк;
- другой харнес: главный `AGENTS.md`, `CLAUDE.md` симлинк;
- unknown: ничего не трогать, раскладку только показать в отчёте.

```sh
for f in CLAUDE.md AGENTS.md; do
  if [ -L "$f" ]; then echo "$f -> $(readlink "$f")"
  elif [ -f "$f" ]; then echo "$f файл, строк: $(wc -l < "$f" | tr -d ' ')"
  else echo "$f нет"; fi
done
```

Что делать. Пример для Claude Code, при другом харнесе имена меняются местами:

| Что видно | Что сделать |
|---|---|
| `CLAUDE.md` файл, `AGENTS.md -> CLAUDE.md` | ничего |
| `AGENTS.md` файл, `CLAUDE.md -> AGENTS.md` | `rm CLAUDE.md && mv AGENTS.md CLAUDE.md && ln -s CLAUDE.md AGENTS.md` |
| в файле одна строка с именем второго файла (`[ "$(cat CLAUDE.md)" = AGENTS.md ]`) | это симлинк, сломанный при распаковке: удалить его и дальше по строкам ниже |
| есть только `AGENTS.md` | `mv AGENTS.md CLAUDE.md && ln -s CLAUDE.md AGENTS.md` |
| есть только `CLAUDE.md` | `ln -s CLAUDE.md AGENTS.md` |
| нет обоих | `touch CLAUDE.md && ln -s CLAUDE.md AGENTS.md` |
| оба настоящие, текст одинаковый (`cmp -s CLAUDE.md AGENTS.md`) | `rm AGENTS.md && ln -s CLAUDE.md AGENTS.md` |
| оба настоящие, текст разный | не трогать; сказать человеку, что сначала текст надо свести в один файл |

Windows. Симлинки там часто не работают: после распаковки архива `CLAUDE.md` становится файлом с текстом `AGENTS.md`, а `ln -s` в Git Bash может сделать копию. Тогда при любом харнесе главный файл `AGENTS.md`, а в `CLAUDE.md` одна строка `@AGENTS.md`: так Claude Code подключает текст другого файла.

После правки проверить, что второй файл стал симлинком (`[ -L AGENTS.md ]`), а текст правил на месте.

## 4. Папка скиллов

Скиллы лежат в `.agents/skills/`, это настоящая папка. `.claude/skills` это симлинк на неё целиком: так Claude Code видит те же скиллы, что и Codex.

```sh
[ -d .agents/skills ] && [ ! -L .agents/skills ] && echo "✓ .agents/skills" || echo "✗ .agents/skills"
[ -L .claude/skills ] && [ -d .agents/skills ] && [ "$(cd .claude/skills 2>/dev/null && pwd -P)" = "$(cd .agents/skills && pwd -P)" ] && echo "✓ .claude/skills" || echo "✗ .claude/skills"
```

Как починить:

- нет `.agents/skills`: `mkdir -p .agents/skills`;
- `.claude/skills` нет, ведёт не туда или стал файлом с текстом `../.agents/skills`: `mkdir -p .claude && rm -f .claude/skills && ln -s ../.agents/skills .claude/skills`;
- `.claude/skills` настоящая папка: показать человеку, что в ней лежит. Скиллы, которых нет в `.agents/skills`, перенести туда после его «да», потом заменить папку симлинком;
- Windows без симлинков: в PowerShell `New-Item -ItemType Junction -Path .claude\skills -Target (Resolve-Path .agents\skills)`, прав администратора это не требует.

## 5. Файл правил и отделы

В файле правил штаба четыре части: роль агента, карта отделов со ссылками на их папки, границы (что агент делает только после подтверждения) и стоп-правила (чего нельзя никогда). Длина до 500 строк.

Отдел это соседняя папка штаба, упомянутая в файле правил как `../имя` или как `имя` в обратных кавычках, если папка `../имя` существует. Если карта отделов вынесена в `projects.md`, он читается вместе с файлом правил. В файле правил отдела нужна обратная ссылка на штаб: без неё агент, открытый в отделе, не знает, чей это отдел и где `me.md`.

В командах ниже `R` это главный файл правил из шага 3:

```sh
R=CLAUDE.md
HQ=$(basename "$(pwd -P)")
HQRE=$(printf '%s' "$HQ" | sed 's/[.[\*^$()+?{|]/\\&/g')
echo "строк в $R: $(wc -l < "$R" | tr -d ' ')"
[ -f projects.md ] && ! grep -q 'projects\.md' "$R" && echo "✗ файл правил не ведёт в projects.md"
grep -ohE '\.\./[^/)`"[:space:],;:«»]+' "$R" projects.md 2>/dev/null | sed -E 's#\.+$##' | sort -u |
  while IFS= read -r p; do [ -e "$p" ] || echo "✗ нет папки $p"; done
D=$({ grep -ohE '\.\./[^/)`"[:space:],;:«»]+' "$R" projects.md; grep -ohE '`[^`]+`' "$R" projects.md | tr -d '`'; } 2>/dev/null |
  sed -E 's#^\.\./##; s#/.*##; s#\.+$##' | sort -u |
  while IFS= read -r d; do [ -n "$d" ] && [ "$d" != "$HQ" ] && [ "${d#.}" = "$d" ] && [ -d "../$d" ] && echo "$d"; done)
[ -n "$D" ] || echo "✗ в правилах нет ни одного отдела"
printf '%s\n' "$D" | while IFS= read -r d; do
  [ -n "$d" ] || continue
  f=""; for n in AGENTS.md CLAUDE.md; do [ -f "../$d/$n" ] && { f="../$d/$n"; break; }; done
  if [ -z "$f" ]; then echo "✗ $d: у отдела нет файла правил"
  elif grep -qE "(\.\./|/|\`)$HQRE([^[:alnum:]_-]|\$)" "$f"; then echo "✓ $d: связь в обе стороны"
  else echo "✗ $d: связь в одну сторону, в $f нет ссылки на штаб"; fi
done
```

Роль, границы и стоп-правила агент ищет в файле правил по смыслу: заголовки могут называться иначе. Нашёл, тогда ✓ и короткая цитата. Не нашёл, тогда ✗.

| ✗ | Как починить |
|---|---|
| файл правил пустой | собрать вместе с человеком по образцу ниже, его словами |
| длиннее 500 строк | подробности вынести в отдельные файлы, в правилах оставить строку-маршрут «для такой задачи открой такой файл» |
| нет роли, границ или стоп-правил | спросить человека одной строкой и вписать его ответ |
| нет ни одного отдела | добавить строку отдела: имя и путь `../<папка>` |
| нет папки `../имя` | поправить путь или убрать строку |
| связь в одну сторону | в файл правил отдела дописать строку: «Это отдел штаба `../<папка штаба>`, там общие правила и `me.md`» |
| у отдела нет файла правил | сказать человеку: файл правил отдела пишет он сам |

Образец для пустого файла правил:

```markdown
# Штаб

Роль агента: <одна строка>.

## Отделы
- <отдел>: `../<папка>`

## Границы
- Прежде чем менять файлы вне этой папки, покажи план и жди слова «выполняй».

## Стоп-правила
- Не отправляй сообщения и письма людям без моего подтверждения.

Кто я и как со мной работать: `me.md`.
```

## 6. me.md

`me.md` держит контекст человека: его роль, чем он занят, как ему удобно работать с агентом, чего делать нельзя.

```sh
if [ -f me.md ]; then echo "строк в me.md: $(wc -l < me.md | tr -d ' ')"; grep -nE '\[ВСТАВИТЬ|TODO|\{\{|<[^>]+>' me.md; else echo "✗ me.md нет"; fi
grep -q 'me\.md' "$R" || echo "✗ файл правил не ведёт в me.md"
```

- `me.md` нет или это заготовка (плейсхолдеры, пустые разделы): ✗. Следующий шаг: скилл `interview-me` с целью «собери `me.md`: моя роль, чем я занят, как мне удобно с тобой работать, чего делать нельзя».
- `me.md` заполнен: прочитать целиком и сказать человеку одной-двумя строками, что агент теперь о нём знает.
- Файл правил не называет `me.md`: новое окно агента может его не прочитать. Предложить строку «Кто я и как со мной работать: `me.md`». В Claude Code строка `@me.md` в `CLAUDE.md` подгружает файл при старте.

## 7. Отчёт человеку

Одна таблица, под ней три строки.

| Проверка | Итог | Как починить |
|---|---|---|
| Штаб | ✓ `~/hq` | |
| Харнес и модель | ✓ Claude Code (cli) <версия>, <модель> | |
| Главный файл правил | ✓ `CLAUDE.md`, `AGENTS.md` симлинк, исправлено | |
| Папка скиллов | ✓ | |
| Файл правил | ✗ 12 строк, нет стоп-правил | дописать стоп-правило, показать правку |
| Отдел `learn` | ✗ связь в одну сторону | строка про штаб в `../learn/AGENTS.md` |
| `me.md` | ✓ | |

1. Что исправлено сейчас и каким коммитом.
2. Одна-две строки о человеке из `me.md`.
3. Один следующий шаг. `me.md` нет или заготовка: `interview-me`. Есть ✗ в правилах: показать правку и спросить «да». Всё ✓: предложить «покажу штаб в 3D» скиллом `pc-avatar`, если он есть в папке скиллов.

## 8. Git

Если штаб это git-репо (`git rev-parse --is-inside-work-tree`), закоммитить только свои правки. Чужие изменения в коммит не попадают:

```sh
git add -- <свои файлы> && git commit -m "chore(hq): <что сделано>" -- <свои файлы>
```

Push делать, если так велят правила человека (файл правил штаба или его глобальные правила), иначе спросить. Так же в папке отдела, если человек сказал «да» на правку её правил.
