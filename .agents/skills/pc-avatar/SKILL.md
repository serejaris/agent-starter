# pc-avatar: аватар в штабе

Агент рисует себя в штабе человека. На сцене робот: тело это харнес, голова это модель. Голову модель делает себе сама при первом запуске в штабе, дальше робот не меняется. Робот обходит штаб и отделы по кругу, читает их файлы правил и записывает файлы. Справа видны окно папки штаба и окно сессии агента.

Плеер сцены лежит рядом с этим файлом: `player.html`, один HTML-файл. Скилл копирует его в штаб и кладёт рядом `scene.js` с данными сцены. Сцена открывается двойным кликом, сервер и интернет не нужны. Там же `kit.json`, набор деталей головы.

Скилл пишет в штаб два файла, `avatar/index.html` и `avatar/scene.js`. Когда модель делает себе робота, он ещё пишет `stack/avatars.json`. В штабе с git он дописывает строку `avatar/` в `.gitignore` и коммитит `stack/avatars.json`. Больше в штабе ничего не меняется. Все строки на сцене берутся из файлов и из запроса человека, агент ничего не сочиняет.

Команды даны для macOS и Linux (zsh, bash). На Windows агент делает то же средствами PowerShell.

## 1. Найти штаб

Шаг 1 скилла `hq`. Дальше команды выполняются в папке штаба.

## 2. Кто я

Тело робота это харнес. Он записан в `stack/harness.md`, строка «Харнес». Файла нет: харнес определяется по таблице шага 2 скилла `hq`. Сам файл пишет скилл `hq`, этот скилл его не создаёт.

| Харнес | `agent.harness` |
|---|---|
| Claude Code | `claude-code` |
| Codex | `codex` |
| Cursor | `cursor` |
| Antigravity | `antigravity` |
| Hermes | `hermes` |
| OpenClaw | `openclaw` |
| ChatGPT | `chatgpt` |
| Grok | `grok` |

Харнеса нет в таблице: взять ближайший вид и сказать об этом человеку. `agent.harnessName` это имя харнеса как есть, например `Claude Code`: лента на теле и шапка окна сессии.

Голова это модель. Модель агент называет сам: она записана в его системном промпте или в настройках харнеса. Модель неизвестна: шаг 3 пропустить, поля `agent.avatar` в сцене нет, на роботе остаётся родная голова вида.

## 3. Сделай себе робота

Ключ робота `<agent.harness>/<семейство модели>`. Семейство это имя модели одним словом, без версии, строчными: у Claude Opus 5.5 в Claude Code ключ `claude-code/opus`, у модели GPT в Codex `codex/gpt`. Все роботы штаба лежат в одном файле, `stack/avatars.json`:

```sh
cat stack/avatars.json 2>/dev/null
```

Запись с этим ключом есть: взять её, робот не меняется. Новая версия модели сохраняет робота, в записи меняется только `tape`. Человек просит сделать робота заново: модель заново выбирает цвет, глаза и примету в пределах той же редкости и заменяет запись с этим ключом. Редкость и `shiny` берутся из записи: редкость выпадает один раз, бросок не повторяется.

Записи нет: бросить редкость один раз. Бросок не переигрывать, берётся то, что выпало.

```sh
r=$((RANDOM % 100))
if [ $r -lt 60 ]; then echo common; elif [ $r -lt 85 ]; then echo uncommon; elif [ $r -lt 95 ]; then echo rare; elif [ $r -lt 99 ]; then echo epic; else echo legendary; fi
[ $((RANDOM % 100)) -eq 0 ] && echo shiny
```

Строка `shiny` в выводе: робот блестящий, `"shiny": true`. В PowerShell то же число даёт `Get-Random -Maximum 100`.

Прочитать `kit.json` из папки этого скилла. Редкости по возрастанию: `common`, `uncommon`, `rare`, `epic`, `legendary`. Открыты детали, у которых `from` не выше выпавшей редкости. Из открытого модель сама выбирает себе цвет (`palettes`), глаза (`eyes`) и примету (`signs`): то, что подходит ей. В `tape` имя модели с версией строчными, `opus 5.5`. В `made` сегодняшняя дата, `date +%F`.

Дописать запись в `stack/avatars.json` инструментом записи файлов, по записи на строку. Файла нет: создать его вместе с папкой `stack/`. Записи с другими ключами не трогать.

```json
{
  "claude-code/opus": {"rarity": "uncommon", "shiny": false, "head": {"color": "clay-light", "eyes": "ring", "sign": "dish"}, "tape": "opus 5.5", "made": "2026-09-28"}
}
```

Файл изменён: проверить, что он читается (нужен `node`, без него проверка пропускается). Штаб это git-репо: закоммитить только этот файл.

```sh
node -e 'console.log(Object.keys(JSON.parse(require("fs").readFileSync("stack/avatars.json","utf8"))).join(" "))'
git rev-parse --is-inside-work-tree >/dev/null 2>&1 && git add -- stack/avatars.json && git commit -m "chore(hq): робот <ключ>" -- stack/avatars.json
```

## 4. Собрать сцену

Главный файл правил `R` назван в `stack/harness.md`, строка «Главный файл правил». Файла нет: это тот из `CLAUDE.md` и `AGENTS.md`, где лежит текст правил. Второй файл симлинк на него или одна строка `@AGENTS.md` (шаг 3 скилла `hq`).

```sh
R=CLAUDE.md                                                   # главный файл правил
basename "$(pwd -P)"                                          # hq.folder
grep -v '^[[:space:]]*$' "$R" | head -n 12                    # hq.rules
[ -f me.md ] && grep -v '^[[:space:]]*$' me.md | head -n 6    # hq.me
{ printf '%s\n' .agents AGENTS.md CLAUDE.md me.md; command ls -1 | LC_ALL=C sort; } | awk '!s[$0]++' |
  while IFS= read -r f; do
    [ "$f" = avatar ] && continue
    if [ -L "$f" ]; then echo "$f → $(readlink "$f")"; elif [ -d "$f" ]; then echo "$f/"; elif [ -e "$f" ]; then echo "$f"; fi
  done | head -n 8                                            # hq.files
```

Отделы. Выполнить строки `HQ=…` и `D=…` из шага 5 скилла `hq`, потом взять первые шесть отделов по порядку упоминания в файле правил:

```sh
printf '%s\n' "$D" | while IFS= read -r d; do
  [ -n "$d" ] && echo "$(cat "$R" projects.md 2>/dev/null | grep -boF -e "../$d" -e "\`$d" | head -n 1 | cut -d: -f1) $d"
done | sort -n | head -n 6 | cut -d' ' -f2
```

Для каждого отдела `d` строки связи без разметки, заголовок и начало его файла правил:

```sh
grep -hF -e "../$d" -e "\`$d" "$R" projects.md 2>/dev/null |
  sed -E 's/\*\*|`//g; s/^[[:space:]]*([-*+]|#+)[[:space:]]+//; s/^\|[[:space:]]*|[[:space:]]*\|$//g; s/[[:space:]]*\|[[:space:]]*/: /g'
f=../$d/AGENTS.md; [ -f "$f" ] || f=../$d/CLAUDE.md
[ -f "$f" ] && grep -m 1 '^# ' "$f"                          # заголовок
[ -f "$f" ] && grep -v '^[[:space:]]*$' "$f" | head -n 12    # начало файла правил
```

| Поле | Что писать |
|---|---|
| `task` | сообщение человека, с которого начался запуск, дословно |
| `agent` | `harness` и `harnessName` из шага 2. `avatar`: запись робота из шага 3 вместе с ключом, `{"claude-code/opus": {…}}` |
| `hq.folder` | имя папки штаба |
| `hq.rulesFile` | имя главного файла правил |
| `hq.rules` | первые непустые строки файла правил, до 12 |
| `hq.me` | первые непустые строки `me.md`, до 6. Нет файла: `null` |
| `hq.files` | вывод команды выше: папка со слешем, симлинк со стрелкой. Папку `avatar/` плеер покажет сам, когда агент запишет файлы |
| `departments[].folder` | имя папки отдела |
| `departments[].link` | самая короткая из строк связи. Длиннее ~80 знаков: дословный кусок этой строки с папкой отдела, по знакам препинания |
| `departments[].title` | имя отдела из заголовка `# ` его файла правил, дословно без `#`. Если в заголовке есть « — », берётся часть после тире: «Отдел продаж» из «# Sales — Отдел продаж», «Отдел обучения» из «# Отдел обучения». Подпись это имя отдела. Заголовка нет, он совпадает с именем папки или не называет отдел («agent guide»): `null`, на стене останется только лента папки |
| `departments[].rules` | первые непустые строки файла правил отдела, до 12. Нет файла: `null` |
| `written` | `["avatar/index.html", "avatar/scene.js"]`. Робот сделан или изменён в этом запуске: первым ещё `stack/avatars.json` |

Строки берутся дословно, без пересказа. Разметку markdown скилл убирает только из строк связи: они стоят в окне сессии.

## 5. Записать два файла

```sh
mkdir -p avatar
cp <папка этого скилла>/player.html avatar/index.html
```

`avatar/scene.js` агент пишет своим инструментом записи файлов: одно присваивание `window.SCENE = {…};`, значение в формате JSON. Кавычки `"` и обратные слеши внутри строк экранируются. Пример из проверочного штаба, списки строк укорочены:

```js
window.SCENE = {
  "version": 1,
  "task": "сделай себе робота",
  "agent": {
    "harness": "claude-code",
    "harnessName": "Claude Code",
    "avatar": {"claude-code/opus": {"rarity": "uncommon", "shiny": false, "head": {"color": "clay-light", "eyes": "ring", "sign": "dish"}, "tape": "opus 5.5", "made": "2026-09-28"}}
  },
  "hq": {
    "folder": "hq",
    "rulesFile": "AGENTS.md",
    "rules": ["# Штаб", "Роль агента: помощник Ани в учёбе и работе, ведёт её задачи по отделам.", "Обо мне: me.md. Прочитай его в начале разговора.", "## Отделы", "Обучение: ../corp-learn. Задачи отдела лежат в ../corp-learn/tasks/."],
    "me": ["Пример me.md: вымышленный участник для проверки аватара.", "# Обо мне", "Аня, продуктовый дизайнер в студии из пяти человек."],
    "files": [".agents/", "AGENTS.md", "CLAUDE.md → AGENTS.md", "me.md", "README.md", "stack/"]
  },
  "departments": [
    {
      "folder": "corp-learn",
      "title": "Отдел обучения",
      "link": "Обучение: ../corp-learn. Задачи отдела лежат в ../corp-learn/tasks/.",
      "rules": ["# Отдел обучения", "Транскрипты уроков Personal Corp 3 и учебные задачи человека.", "## Начало разговора"]
    }
  ],
  "written": ["stack/avatars.json", "avatar/index.html", "avatar/scene.js"]
};
```

Повторный запуск перезаписывает оба файла. Проверить, что сцена читается (нужен `node`, без него шаг пропускается):

```sh
node -e 'const w={};require("vm").runInNewContext(require("fs").readFileSync("avatar/scene.js","utf8"),{window:w});const s=w.SCENE;console.log(s.agent.harness,Object.keys(s.agent.avatar||{}).join(),s.departments.length)'
```

Штаб это git-репо, а папка `avatar/` ещё не в `.gitignore`: дописать туда строку `avatar/`, папка собирается заново при каждом запуске. Сказать человеку, что `.gitignore` изменён.

```sh
if git rev-parse --is-inside-work-tree >/dev/null 2>&1 && ! git check-ignore -q avatar/scene.js; then
  [ -s .gitignore ] && [ -n "$(tail -c 1 .gitignore)" ] && echo >> .gitignore
  echo 'avatar/' >> .gitignore && echo "в .gitignore дописана строка avatar/"
fi
```

## 6. Открыть

| Система | Команда |
|---|---|
| macOS | `open avatar/index.html` |
| Linux | `xdg-open avatar/index.html` |
| Windows | `start "" avatar\index.html` |

Плеер без `scene.js` рядом показывает встроенный пример: штаб `hq`, отдел `corp-learn` и вопрос «Что ты знаешь обо мне и где мой отдел обучения?». Такая сцена вместо штаба человека значит, что `scene.js` не прочитался: проверить его командой из шага 5.

## 7. Ответ человеку

Одна-две строки: кто на сцене (харнес и модель), сколько отделов, путь к `avatar/index.html`. Если харнес заменён ближайшим видом или дописан `.gitignore`, сказать об этом там же.

Робот сделан в этом запуске: ещё одна строка, какая редкость выпала и что модель себе выбрала. Все детали набора видны в генераторе: открыть `avatar/index.html` и дописать к адресу `?generator`.

## Пример: робот Opus 5.5

Запись `example` в `kit.json`: робот, которого Claude Opus 5.5 сделал себе в Claude Code. Выпала редкая, выбраны глина, глаза-пилюли и орбита. Тело это харнес Claude Code без изменений. Голова светлее корпуса, с кольцом крепления на шее и наушниками харнеса, на лбу лента `opus 5.5 ★★★`. Над головой маячок, вокруг него тонкое наклонное кольцо-орбита с бусиной. Бусина бежит медленно и ускоряется, когда агент думает. На вызове инструмента маячок теплеет, а когда файл записан, глаза на миг становятся дугами. В другом штабе редкость выпадет заново, и робот будет свой. Агента одного и крупно показывает адрес сцены с `?portrait` на конце.
